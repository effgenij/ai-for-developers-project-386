## Project Overview

Calendar booking system. An owner creates event types; guests book available slots without registration. One booking per time slot across all event types.

**Stack:** React 19 + Vite (frontend), Fastify 5 + Node.js 22 (backend), TypeSpec → OpenAPI 3.0 (API spec), Turborepo + npm workspaces (monorepo), mise (tool/task manager).

## Development Commands

Requires [mise](https://mise.jdx.dev/) — it installs Node.js 22.22.2 automatically.

```bash
mise install            # install Node.js
mise run install        # npm install for all workspaces

mise run dev            # start frontend (port 5173) + backend (port 3000)
mise run dev:frontend   # frontend only
mise run dev:backend    # backend only

mise run build          # build all packages
mise run check          # TypeScript type-check all packages
mise run lint           # lint all packages
mise run test           # run all tests

mise run spec           # compile TypeSpec → OpenAPI
mise run spec:watch     # watch + recompile TypeSpec on changes
```

To run turbo commands targeting a single app directly:
```bash
npx turbo run dev --filter=@repo/frontend
npx turbo run dev --filter=@repo/backend
npx turbo run build --filter=@repo/api-spec
```

## Monorepo Structure

```
apps/
  frontend/    React 19 + Vite — package name @repo/frontend
  backend/     Fastify 5 — package name @repo/backend
packages/
  api-spec/          TypeSpec source (main.tsp) → tsp-output/openapi.yaml
  typescript-config/ Shared tsconfig bases (base.json, frontend.json)
```

## Architecture

**API contract flow:** `packages/api-spec/main.tsp` is the single source of truth. Running `mise run spec` compiles it to `packages/api-spec/tsp-output/openapi.yaml`. Both frontend and backend should conform to this spec.

**Backend entry point:** `apps/backend/src/server.ts` starts Fastify; `apps/backend/src/app.ts` exports `buildApp()` which registers routes. Routes are added to `buildApp()` in `app.ts`.

**Frontend entry point:** `apps/frontend/src/main.tsx` → `App.tsx`.

**Turborepo pipeline:** `turbo.json` defines task dependencies. `lint` and `check-types` both depend on `transit` (cross-package type generation). `build` outputs go to `dist/**` and `tsp-output/**`.

**TypeScript configs:** All packages extend from `packages/typescript-config`. Frontend uses `frontend.json`; backend and api-spec use `base.json`.

## Gotchas

- **Vite proxy:** `apps/frontend/vite.config.ts` forwards `/api` → `http://localhost:3000`. Keep all frontend API requests on `/api/...` paths in development.
- **Backend is a stub:** The documented event-types and bookings routes do not exist yet — only `GET /api/health` is implemented. Don't assume the API table below reflects current backend code.
- **TypeSpec output is tracked:** `packages/api-spec/tsp-output/openapi.yaml` is committed. If you edit `main.tsp`, regenerate it (`mise run spec`) and commit the YAML diff too.
- **Tests are a no-op:** `mise run test` runs `turbo test`, but no workspace defines a `test` script yet.
- **Lint is broken:** `mise run lint` fails — ESLint is not installed or configured in either app.
- **Hexlet CI:** `.github/workflows/hexlet-check.yml` is autogenerated. Do not edit, delete, or rename the repository.
- **Doc sync hook:** `CLAUDE.md` and `AGENTS.md` are kept identical via a git pre-commit hook. After cloning, run `mise run install-hooks` (or `mise run install`) to activate it. The hook source lives in `scripts/hooks/pre-commit`.

## API Endpoints

| Method | Path | Description |
|--------|------|-------------|
| GET | `/api/event-types` | List event types |
| POST | `/api/event-types` | Create event type |
| GET | `/api/event-types/:id` | Get event type |
| PATCH | `/api/event-types/:id` | Update event type |
| DELETE | `/api/event-types/:id` | Delete event type |
| GET | `/api/event-types/:id/available-slots?date=YYYY-MM-DD` | Available slots |
| GET | `/api/bookings` | Upcoming bookings |
| POST | `/api/bookings` | Create booking |
| DELETE | `/api/bookings/:id` | Cancel booking |
